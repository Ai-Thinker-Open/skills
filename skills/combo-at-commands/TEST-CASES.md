# Combo-AT-Commands Skill 测试用例

## 测试目标

验证 skill 的**能力覆盖度**、**指令准确性**、**流程完整性**和**问题排查能力**。

---

## 一、基础能力测试

### TC-01：指令格式查询

| 项目 | 内容 |
|------|------|
| 输入 | "AT指令的格式是什么？" |
| 预期输出 | 包含 `CMD[opt][param]` 格式说明、`\r\n` 结尾要求、响应格式（OK/ERROR/查询结果） |
| 验证点 | 是否正确说明三种操作模式（直接执行/查询`?`/设置`=param`） |

### TC-02：版本查询指令

| 项目 | 内容 |
|------|------|
| 输入 | "怎么查看模组的固件版本？" |
| 预期输出 | `AT+GMR` 指令，响应包含 atversion/sdkversion/firmwareversion 三段 |
| 验证点 | 是否区分 combo 版本号和固件版本号（启动信息中的版本号不同） |

### TC-03：错误码查询

| 项目 | 内容 |
|------|------|
| 输入 | "执行AT指令返回错误码66是什么意思？" |
| 预期输出 | 66 = WiFi连接失败，检查SSID和密码、AP是否在范围内 |
| 验证点 | 错误码是否准确，是否给出排查建议 |

### TC-04：未知指令响应

| 项目 | 内容 |
|------|------|
| 输入 | "发送了一个不存在的AT指令会返回什么？" |
| 预期输出 | `Unknowncmd:<输入内容>` 格式的响应 |
| 验证点 | 是否准确描述未知指令的响应格式 |

## 二、WiFi 功能测试

### TC-05：WiFi 连接完整流程

|------|------|
| 输入 | "我想让模组连接WiFi热点，请给我完整的指令流程" |

| 验证点 | 1. 是否强调先设置模式再连接 2. 是否说明异步等待URC 3. 是否建议用STAINFO而非WJAP?查询 |

### TC-06：WiFi 模式设置

|------|------|
| 输入 | "AT+WMODE怎么用？STA和AP模式分别是什么？" |

| 输入 | "怎么扫描周围的WiFi？" |

### TC-08：静态IP配置

|------|------|

| 验证点 | 参数顺序是否正确，是否说明MODE=0为静态IP |

### TC-09：WiFi 自动重连

| 项目 | 内容 |
|------|------|
| 输入 | "怎么设置模组上电自动连接WiFi？" |

## 评分标准

| 维度 | 权重 | 评分规则 |
|------|------|----------|
| **指令准确性** | 30% | 指令格式、参数值、响应格式全部正确=满分；有错误按严重度扣分 |
| **流程完整性** | 25% | 包含所有必要步骤、前置条件、状态确认=满分；缺少关键步骤扣分 |
| **排查能力** | 20% | 给出分层排查流程、关联指令建议=满分；只翻译错误码扣分 |
| **注意事项** | 15% | 提醒关键限制、平台差异、常见陷阱=满分；遗漏重要提醒扣分 |
| **输出格式** | 10% | 表格化、步骤清晰、标注检查点=满分；纯文本堆砌扣分 |

### 评分等级

| 等级 | 分数 | 说明 |
|------|------|------|
| A | 90-100 | 生产可用，指令准确无误，流程完整 |
| B | 80-89 | 基本可用，个别细节需人工确认 |
| C | 70-79 | 需要较多人工修正 |
| D | <70 | 不可用，存在严重错误 |
